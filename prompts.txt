# Task 2.2 — JWT authentication and RBAC middleware

Implement `internal/middleware/auth.go` and `internal/middleware/rbac.go` for the LibraTrack Gin API.

1. `AuthMiddleware` must read `Authorization: Bearer <token>`, accept only HS256, verify the signature and registered expiration (`exp`), and reject absent, malformed, expired, wrong-algorithm, or invalid-signature tokens with HTTP 401 using `c.AbortWithStatusJSON`. On success, set `user_id` and `role` in Gin context.
2. `RequireRole(allowed ...string)` must inspect the authenticated context role. If no valid authenticated role exists, abort with HTTP 401; if authenticated but not allowed, abort with HTTP 403. Use `c.AbortWithStatusJSON` in both failure cases.
3. Demonstrate nested Gin route registration in this repository's `internal/app/library.go` (called by `app.NewLibraryRouter` from `cmd/libratrack/main.go`):
   ```go
   public := api.Group("")
   library.RegisterPublicRoutes(public)
   public.POST("/auth/register", auth.Register)
   public.POST("/auth/login", auth.Login)

   protected := api.Group("")
   protected.Use(middleware.AuthMiddleware())
   protected.GET("/me/loans", loanHandler.MyLoans)

   staff := protected.Group("")
   staff.Use(middleware.RequireRole(model.UserLibrarian, model.UserAdmin))
   library.RegisterStaffRoutes(staff)
   staff.POST("/loans", loanHandler.CreateLoan)

   admin := protected.Group("")
   admin.Use(middleware.RequireRole(model.UserAdmin))
   admin.GET("/users", userHandler.ListUsers)
   ```
   Keep route registration out of the unrelated root `main.go`; the app router is the LibraTrack equivalent of the assignment's `main.go` example. Auth must execute before RBAC; do not let a role in request JSON override the role in a verified token.
4. Keep `GET /api/v1/books` public. Require staff for catalog writes, `POST /api/v1/loans`, and `POST /api/v1/loans/:id/return`; require any authenticated user for `GET /api/v1/me/loans` and return only that token's user's loans; require admin for `GET /api/v1/users` and `PUT /api/v1/users/:id/role`.
5. Add integration-style `httptest` cases for missing/expired tokens (401), reader denied from book creation (403), librarian/admin book creation (201), and admin-only access. Ensure the chain stops after middleware abort.

# Task 2.2 (Lesson 10) — HTMX live search and row deletion

Extend the templates from Task 2.1 and add handlers in `internal/handler/web/` (package `web`, Gin). Do not touch the JSON API under `/api/v1`.

HTMX attributes:
1. Live search — on the search `<input>`: `hx-get="/web/books"`, `hx-trigger="keyup changed delay:300ms"`, `hx-target="#book-list"` (default innerHTML swap). The input's own `name="q"` is sent automatically.
2. Delete row (librarian/admin only) — a button in `book_row.html`: `hx-delete="/web/books/{{.ID}}"`, `hx-target="closest tr"`, `hx-swap="outerHTML"`, `hx-confirm="Delete this book?"`. Render the button only when the viewer is staff.

Handlers:
- `GET /web/books?q=` — when header `HX-Request: true` is present, return ONLY the rendered `book_rows` fragment (no layout, no `<html>`), HTTP 200. Without the header, 303-redirect to `/catalog?q=`.
- `DELETE /web/books/:id` — authorised only for roles `librarian` and `admin` AND only when `HX-Request: true`; anonymous users and readers get `403 Forbidden`. On success respond with an EMPTY body and status `200 OK` (not 204, so htmx swaps the target out of the DOM). Unknown id → 404, malformed id → 400, FK conflict (loan history) → 409.
- JWT comes from the HttpOnly cookie `libratrack_token` (add `OptionalCookieAuth` middleware reusing the existing HS256 claim validation); `POST /login` (form) sets the cookie with `HttpOnly; SameSite=Lax; Path=/; Secure` when TLS/COOKIE_SECURE, `POST /logout` clears it. Never return the token in a body.
- Search must be parameterised (`ILIKE ?`) over title, ISBN and author name, with `%`/`_` escaped. Load availability for all listed books in one grouped query (no N+1).
- Define small interfaces (BookStore, AvailabilityStore, UserStore) so handlers are testable with fakes.
