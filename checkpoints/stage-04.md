# Звіт-контрольна точка: етап 4

**Тема:** список, сортування, пагінація та фільтр  
**Варіант:** `devices`  
**Статус:** виконано за видимими тестами  
**Дата:** 2026-10-06

## Мета

Додати `GET /api/v1/devices` зі стабільним порядком, пагінацією та фільтром за четвертим обов’язковим полем варіанта `devices` — `type`.

## Що реалізовано

- У [internal/repository/memory.go](../internal/repository/memory.go) додано `List()`: сховище створює snapshot під `RLock`, повертає копії ресурсів і сортує їх за ID за зростанням. Для порожнього сховища повертається порожній зріз, який серіалізується як `[]`.
- У [internal/handler/device.go](../internal/handler/device.go) collection-обробник підтримує `GET` поряд із наявним `POST`.
- `page` і `limit` мають значення за замовчуванням `1` і `10`; некоректні або менші за 1 значення повертають `400 invalid_pagination`. Значення `limit` понад 100 обмежуються до 100.
- Фільтр `type` застосовується до пагінації, використовує точний регістрозалежний збіг; відсутнє або порожнє значення вимикає фільтр.
- Перед обчисленням меж зрізу перевіряється, чи сторінка існує. Це дозволяє обробляти дуже великі `page` без переповнення арифметики й без паніки.
- Порожня колекція, відсутні збіги фільтра та сторінка за межами результатів повертають `200` і `[]`.

## Перевірки

Виконано:

```text
gofmt -w internal/repository/memory.go internal/handler/device.go
go test ./internal/app -run TestStage4 -v
go test ./internal/app -run 'TestStage1|TestStage2|TestStage3|TestStage4' -v
go vet ./...
```

**Результат:** усі видимі тести етапу 4 пройшли; спільний запуск тестів етапів 1–4 пройшов; `go vet ./...` завершився без зауважень.

Тести прямо не охоплюють кожну граничну вимогу README (зокрема `limit > 100`, регістрозалежність фільтра та `page=9223372036854775807`); ці випадки враховані в реалізації, але окремо в цій перевірці не запускалися. `go test -race ./...` залишено для фінального етапу 5.
