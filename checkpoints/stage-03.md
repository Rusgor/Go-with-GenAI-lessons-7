# Звіт-контрольна точка: етап 3

**Тема:** повне оновлення через PUT і видалення через DELETE  
**Варіант:** `devices`  
**Статус:** виконано за видимими тестами  
**Дата:** 2026-10-06

## Мета

Реалізувати повну заміну ресурсу пристрою, видалення та правила збереження ідентифікатора й часових міток відповідно до [README.md](../README.md).

## Що реалізовано

- У [internal/repository/memory.go](../internal/repository/memory.go) додано атомарні операції `Update` і `Delete`, захищені м’ютексом. Для них handler більше не виконує окрему перевірку через `Get`, яка могла б створити проміжок для гонки.
- PUT використовує чинні парсер ID і валідатор запиту з етапу 2 та зберігає порядок **ID → тіло → існування**. При успіху повертається `200` із збереженим ресурсом.
- Під час повної заміни `id` та `created_at` залишаються незмінними, `updated_at` оновлюється і не рухається назад у часі. Не передані необов’язкові поля замінюються на `null`.
- DELETE атомарно видаляє ресурс і повертає `204` без тіла. Повторне видалення або GET після видалення повертає `404 not_found`.
- Лічильник ID збережено при видаленні; після видалення номер не перевикористовується. Лічильник тепер ширший за `uint32`, щоб визначити вичерпання простору ID і не допустити переповнення до нуля; у такому разі створення повертає контрольований `500 internal_server_error`.
- Зміни HTTP-обробників розміщені в [internal/handler/device.go](../internal/handler/device.go).

## Перевірки

Виконано:

```text
gofmt -w internal/repository/memory.go internal/handler/device.go
go test ./internal/app -run TestStage3 -v
go test ./internal/app -run 'TestStage1|TestStage2|TestStage3' -v
go vet ./...
```

**Результат:** усі Stage 3 тести пройшли; спільний запуск етапів 1–3 також пройшов; `go vet ./...` завершився без зауважень.

Повний `go test -race ./...` ще не запускався. Він запланований для завершального етапу перевірки конкурентності після реалізації етапів 4–5.

## Що перевірено тестами

Тести підтвердили, що PUT замінює поля й зберігає ID та `created_at`, зміни залишаються доступними через GET, відсутні optional-поля стають `null`, DELETE дає порожню відповідь 204 і видаляє ресурс, повторні звернення отримують 404, а ID після видалення не перевикористовується.
